# pf-campaigns 인수인계 (UI를 고칠 때 꼭 읽기)

체험단 대행 업무용 관리자 화면(`/admin`)과 지원 접수 페이지. 구글 시트(`체험단_자동화_설정`)와 양방향으로 연결돼 있다.
**UI는 마음대로 바꿔도 되지만, 아래 업무 규칙과 시트 연동 동작은 바꾸지 말 것.**

## 먼저 알아둘 것
- 이 프로젝트의 Next.js는 일반 버전과 다르다. 코드를 쓰기 전에 `node_modules/next/dist/docs/`의 해당 문서를 읽을 것 (`AGENTS.md` 참고).
- `main`에 푸시하면 Vercel이 바로 운영(pf-campaigns.vercel.app)에 배포한다. 큰 변경은 브랜치로 작업하고 미리보기 주소로 확인한다.
- 환경변수(비밀값, 저장소에 넣지 말 것): `ADMIN_PASSWORD`, `ADMIN_API_SECRET`, `GOOGLE_SHEET_WEBHOOK_URL`, 선택 `ADMIN_SESSION_SECRET`. 값은 Vercel 프로젝트 설정에서 `.env.local`로 옮긴다.

## 구조
- `src/app/admin/page.js` : 관리자 화면 전체 (목록, 지원자 모달, 문자 모달, 폴더, 삭제)
- `src/components/AdminPasswordGate.jsx` : 로그인 화면 (서버 쿠키 방식, 비밀번호는 클라이언트에 없음)
- `src/app/api/admin/session/route.js` : 로그인/로그아웃/상태
- `src/app/api/admin/applications/route.js` : 시트 읽기/쓰기 (GET 목록, POST 수정·공유·삭제·문자)
- `src/app/api/apply/route.js` : 체험단 지원 접수 → 시트
- `src/lib/adminAuth.js`, `src/lib/sheetApi.js`, `src/lib/parser.js`
- `scripts/google-apps-script-admin.js` : 시트에 붙는 Apps Script 웹훅의 사본(실제로 도는 코드는 구글 쪽). 이 파일을 고쳐도 Apps Script에 직접 새 버전으로 배포해야 반영된다.

## 업무 규칙 (바꾸지 말 것)
1. **진행상태 7가지**: 1.신규지원 → 2.예약중 → 3.체험대기중 → 4.포스팅 작성중 → 5.원고 검수중 → 6.발행완료, 그리고 7.드랍. 값 문자열을 그대로 써야 시트와 맞는다 (`STATUS_OPTIONS`).
2. **공유**는 체크박스. 체크하면 병원별 프로젝트룸 시트에 바로 올라간다(10분 대기 없음).
   - 조건이 안 맞으면 올리지 않고 얼럿으로 이유를 보여준다. 예: "블로그지수 입력이 누락되었어요!"
   - 공유 조건: 블로그지수 있음, 시트의 점검 칸이 비어 있음, 고객사 있음, 공유 시작일 이후 신청.
   - 이미 룸에 올라간 지원자는 공유 해제 불가. 안내 문구: "공유된 리스트는 프로젝트룸에서만 삭제가 가능합니다."
3. **완전삭제**는 유지한다 (휴지통 없음, 처리기록 탭에 기록).
4. **월별 발행 집계는 원고 발행일 기준**이다 (신청일이 아님).
5. **연락처, 블로그주소**는 관리자가 수정할 수 있다. 수정하면 룸 모집정보 글과 문자 행도 같이 고쳐진다.
6. 예약일 확정 시 희망 일정 3개 중 선택된 일정을 강조 표시한다. 확정하면 1.신규지원은 2.예약중으로 바뀐다.
7. 3.체험대기중이 되면 블로거 폴더가 만들어지고, 관리자 화면 폴더 영역에 보인다.
8. 문자: 시트 `문자발송` 탭의 문구를 보여주고, 보냄 표시와 문구 수정을 할 수 있다. 이미 보낸 문자는 수정 불가.

## 건드리면 안 되는 것
- 시트의 자동 열(점검, 룸동기값, 키, 자동 원문 등)은 화면에서 쓰지 않는다. 수정 가능한 필드는 서버에서 허용 목록으로 제한돼 있다 (상태, 예약일, 원고 발행일, 발행원고 URL, 성과, 메모, 블로그지수, 연락처, 블로그주소).
- 관리자 API는 로그인 쿠키가 없으면 401. 인증 코드를 우회하거나 목 데이터를 넣지 말 것.
- 시트 요청은 최대 55초 대기(서버 `maxDuration = 60`). 느릴 수 있으니 저장 중 상태 표시와 실패 시 새로고침 흐름을 유지한다.
- 저장은 화면에 먼저 반영하고 실패하면 되돌리는 방식(낙관적 업데이트)이다. UI를 바꿔도 이 흐름은 유지한다.
